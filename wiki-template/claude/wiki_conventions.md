# 위키 작성 규칙

Claude 프로젝트 파일 `claude/wiki_conventions.md`로 둔다. 위키 문서를 쓰거나 반영하는 모든 세션이 먼저 이 파일을 읽는다.

## 프로젝트 정보
- 프로젝트: [프로젝트 이름]
- 위키 목적: [한 줄]
- 대문 문서: `대문` (`wiki_config.json`의 `root`와 같게)

## 위키 경로
반영 스킬은 이 목록에서 지금 연결된 컴퓨터에 있는 경로를 찾는다. 자기 환경에 맞게 고친다.
- Windows: `C:\Users\<사용자>\Documents\<위키폴더>`
- macOS/Linux: `~/Documents/<위키폴더>`

## 문서 형식
- 위치: `pages/<NN_분류>/<파일명>.md`. 파일명은 공백 대신 `_`. title은 파일명과 달라도 된다(예: `Q_FLU.md` → `Q: FLU가 뭐의 약자야`).
- front matter:
  - `title` — 링크 이름. `:`가 들어가면 따옴표로 감싼다.
  - `aliases: [a, b]` — 다른 이름. 기존 title·alias와 겹치면 안 된다(대소문자 무시).
  - `category`, `parent`(상위 문서 title, 존재해야 함), `summary`(한두 문장), `status`, `updated: YYYY-MM-DD`
- `status`: 확정 / 완료 / 진행중 / 검토중 / 가설 / 아이디어 / 폐기 / NO-GO
- **첫 `##` 전 문단이 미리보기다.** 개요를 두세 문장으로 먼저 쓴다.
- 링크: `[[문서]]`, `[[문서|글자]]`, `[[문서#섹션]]`. 표 안에서는 `[[문서\|글자]]`.
- 수식 `$...$`, `$$...$$`. 각주 `[^1]` + `[^1]: 내용`. 박스 `> [!note] 제목` (note·warn·risk·idea).
- 새 문서는 적어도 한 기존 문서에서 링크를 받아야 한다(고아 방지). 대문만 예외.
- 질문에서 나온 문서는 title을 `Q: ...`, category `질문`, parent `질문 기록`으로 하고 `질문 기록` 표에 행을 추가한다. 질문 문서에는 답의 요약과 개념 링크만 두고, 개념 설명은 개념 문서에 쓴다.
- 검증하지 않은 내용은 "확인 필요" 섹션이나 `> [!warn]` 박스에 둔다.
- 결정을 내렸으면 `결정 기록` 표에 한 줄 추가한다.

## 키워드
- "위키!": 방금 질문과 답을 이 규칙대로 문서로 만든다. 컴퓨터가 연결돼 있으면 바로 반영, 아니면 pending에 저장.
- "반영": 쌓인 pending만 위키에 넣는다.

## 위키에 닿지 않는 세션이 할 일
- 새 문서는 `claude/wiki_pending/<NN_분류>/<파일명>.md`에 완성본으로 저장한다.
- 기존 문서 수정은 파일 이름에 "수정"을 넣고 본문을 `[위키 수정 지시]`로 시작한다. 대상 문서, 바꿀 위치(원문 그대로), 바꿀 내용을 쓴다.
- 아래 "반영 대기"에 항목과 "반영 시 함께 할 일"(질문 기록 행, 링크 추가, alias 확인 등)을 적는다.
