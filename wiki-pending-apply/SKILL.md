# 위키 쓰기와 반영

두 가지 명령이 있다. 사용자에게 다시 묻지 말고 끝까지 진행한다. 예외는 기존 문서와 내용이 충돌할 때뿐이다(B-3).

| 사용자의 말 | 할 일 |
|---|---|
| **"위키!"** | A(문서 쓰기) → 컴퓨터가 연결돼 있으면 B(반영)까지 |
| **"반영"**, "pending 반영", "위키 반영" | B(반영)만 |

**지금 연결된 컴퓨터만 본다.** 위키 동기화(commit·push·pull)는 사용자가 직접 한다. 다른 컴퓨터의 상태는 확인하지도 보고하지도 않는다.

# A. 문서 쓰기 ("위키!")

## A-1. 무엇을 쓸지 정하기
- 같은 메시지에 질문이 있으면(예: "1+1은 왜 2야? 위키!") **먼저 질문에 평소처럼 답한다.** 그 답과 질문이 문서의 재료다.
- "위키!"만 단독으로 오면, 직전 "위키!" 이후(없으면 대화 처음부터) 나눈 질문과 답 중 아직 위키에 없는 것이 재료다. 질문이 여러 개면 질문마다 문서를 만든다.
- 재료가 없으면(인사, 잡담뿐) "위키에 남길 질문이 없다"고 한 줄로 말하고 끝낸다.

## A-2. 규칙과 기존 문서 확인
- `project_read`로 `claude/wiki_conventions.md`를 읽는다. 문서 형식, 분류, "현재 문서" 목록이 있다.
- 컴퓨터가 연결돼 있으면(B-1 방식으로 위키 폴더를 찾는다) `pages/`에서 관련 title·alias를 grep해 기존 문서를 직접 확인한다. 연결이 없으면 "현재 문서" 목록을 기준으로 한다.

## A-3. 문서 만들기
`wiki_conventions.md`의 형식을 따른다. 기본 구성:
- **질문 문서 1개**: title `Q: 질문을 짧게`, category `질문`, parent `질문 기록`, `updated`는 오늘 날짜. 본문은 ① 질문 원문 ② 한 문단 답 ③ 개념 링크 ④ 남은 의문. 개념 설명은 여기에 길게 쓰지 않는다.
- **개념 문서**: 답에 나온 핵심 개념이
  - 이미 문서가 있으면 → 링크만 건다. 답에서 새로 알게 된 내용이 있으면 그 문서에 섹션을 추가한다(수정).
  - 문서가 없고 다시 쓰일 개념이면 → 새 개념 문서를 만든다.
  - 지나가는 단어면 → 문서를 만들지 않는다. 빨간 링크도 걸지 않는다.
- **질문 기록**: `질문 기록` 표에 날짜 순서로 행을 추가한다.
- 새 문서는 적어도 한 기존 문서에서 링크를 받게 한다(질문 문서는 질문 기록 표가 그 역할을 한다).
- 결정이 나온 대화면 `결정 기록` 표에도 한 줄 추가한다.
- 확신이 없는 내용은 "확인 필요" 섹션이나 `> [!warn]` 박스에 둔다. 답에 없던 내용을 지어내지 않는다.

## A-4. 어디에 쓸지
- **컴퓨터 연결됨** → pending을 거치지 않고 위키에 바로 쓴다. B-3(쓰기 전 확인) → B-4(파일 쓰기) → B-5(기존 문서 수정) → B-6(빌드)를 그대로 따른다. 그다음 B-1에서 다른 pending이 남아 있으면 같이 반영한다.
- **연결 안 됨** → `project_write`로 `claude/wiki_pending/<NN_분류>/<파일명>.md`에 저장한다. 기존 문서 수정은 파일 이름에 "수정"을 넣고 본문을 `[위키 수정 지시]`로 시작해 대상 문서, 바꿀 위치, 바꿀 내용을 쓴다. `wiki_conventions.md`를 다시 읽고 "반영 대기"에 항목과 "반영 시 함께 할 일"(질문 기록 행 추가 등)을 적어 `project_write`로 저장한다.

## A-5. 보고
- 만든 문서 제목, 고친 기존 문서(한 줄씩)
- 연결됨: 빌드 결과(문서 N개, 경고 0), 마지막 줄 "커밋은 안 했음"
- 연결 안 됨: "pending에 저장함. 컴퓨터를 연결한 세션에서 '위키!'나 '반영'이라고 하면 들어감"

# B. 반영

## B-1. 할 일 파악
- `project_read`로 `claude/wiki_conventions.md`를 읽는다. "위키 경로"와 "반영 대기"(문서별 함께 할 일)가 있다.
- `project_info`로 `claude/wiki_pending/` 아래 문서를 모두 찾는다. 반영 대기 목록과 실제 파일이 다르면 실제 파일을 기준으로 한다. 목록에 없는 파일은 내용을 보고 할 일을 정한다.
- pending 파일은 새 문서이거나 **수정 지시**다(파일 이름에 "수정"이 있거나 본문이 `[위키 수정 지시]`로 시작).
- "반영"으로 왔는데 pending 파일이 없으면 "반영할 문서가 없다"고 한 줄로 말하고 끝낸다.
- 각 pending 문서를 `project_read`로 전부 읽는다.

## B-2. 위키 폴더 찾기
1. `device_bash`로 `ls $HOME/mnt/`를 실행한다. `build.py`와 `pages/`가 있는 폴더가 위키다.
2. 없으면 "위키 경로" 후보에 `device_list_dir`을 실행해 이 컴퓨터에 있는 쪽을 찾고, 그 폴더에 `device_request_folder_access`를 한 번 요청한다(이유: "위키 문서를 로컬 위키에 넣기 위해").
3. 컴퓨터에 닿지 않으면: "반영"으로 왔으면 반영할 수 없다고 말하고 멈춘다. "위키!"로 왔으면 A-4의 "연결 안 됨"으로 간다.

## B-3. 쓰기 전 확인
위키 루트에서 한 번에 확인한다.
- 줄끝: `file pages/00_대문/위키_사용법.md`처럼 기존 문서 하나에 `file`을 실행한다. 새 파일과 수정한 파일도 같은 줄끝(CRLF 또는 LF)으로 맞춘다.
- 새 문서의 대상 파일이 이미 있는지 확인한다.
  - 내용이 같으면(줄끝 차이 무시) 쓰지 않는다.
  - 다르면 덮어쓰지 않는다. diff를 보여 주고 어떻게 할지 묻는다.
- 새 문서의 title·`aliases`가 기존 문서의 title·alias와 겹치는지(대소문자 무시) grep으로 확인한다.
- 새 문서의 `parent`가 실제로 있는 문서 title인지 확인한다.

## B-4. 파일 쓰기
- `device_bash`에서 따옴표 친 heredoc(`<<'EOF'`)으로 쓴다. 따옴표가 없으면 `$`, `\` 수식이 깨진다. pending에서 온 내용은 project_read 결과를 그대로 옮긴다. 요약하거나 고치지 않는다.
- CRLF 위키면 쓴 뒤 `sed -i 's/$/\r/' <파일>`을 실행한다.
- git 스테이징·커밋은 하지 않는다.

## B-5. 함께 할 일·기존 문서 수정
반영 대기, 수정 지시, A-3에서 정한 수정을 한다. 새 문서가 생겼으면 적어도 다음을 확인한다.
- 질문 문서(`Q: ...`)는 `pages/00_대문/질문_기록.md` 표에 날짜 순서로 행이 있어야 한다.
- 새 문서는 관련 기존 문서에서 들어오는 링크가 있어야 한다(고아 방지).

치환은 아래 함수로 한다. 정확히 1회 일치할 때만 바꾼다. 파일을 `\n`으로 정규화해 다루고 저장할 때 원래 줄끝으로 되돌린다. 스크립트는 위키 밖(`$HOME/edit.py`)에 두고 위키 `pages/`에서 실행한다.

```python
def load(p): return open(p, encoding='utf-8', newline='').read().replace('\r\n', '\n')
def save(p, s, crlf): open(p, 'w', encoding='utf-8', newline='').write(s.replace('\n', '\r\n') if crlf else s)
def rep(s, old, new, tag):
    n = s.count(old)
    if n != 1: print("SKIP", tag, n); return s
    print("OK", tag); return s.replace(old, new)
```

- old 문자열은 먼저 `grep -n`/`sed -n`으로 실제 줄을 보고 복사한다. 메모의 문장을 그대로 믿지 않는다.
- `SKIP`이 나오면 파일을 다시 읽어 맞는 위치를 찾고 다시 적용한다. 한 파일의 치환이 모두 OK일 때만 저장한다.
- 표 안 링크에 `|`가 들어가면 `\|`로 쓴다.
- 해결된 "확인 필요" 항목이 다른 문서에 남아 있으면 같이 정리하고 보고에 한 줄로 적는다.

## B-6. 빌드
- 위키 루트에서 `python3 build.py`를 실행한다. 고치는 중간에는 `python3 build.py --check`로 점검만 해도 된다.
- 정상 출력은 `문서 N개`와 `→ wiki_data.js 작성 완료` 두 줄이다. `[경고]`(제목/별칭 중복, parent 없음, 대문 없음), `빨간 링크`, `고아 문서`가 나오면 고치고 다시 빌드한다. 경고 0이 끝 조건이다.
- 빨간 링크가 함께 들어온 다른 pending 문서를 가리키면 그 문서를 마저 반영한다. 정말 없는 문서면 링크를 지우거나 기존 문서로 바꾸고 보고에 적는다.

## B-7. 프로젝트 정리
- 반영한 pending 파일을 `project_delete`로 지운다.
- `wiki_conventions.md`를 **다시 읽고** 고친다(그사이 다른 세션이 항목을 추가했을 수 있다).
  - 반영한 항목을 "반영 대기"에서 지운다. 남은 것이 없으면 "없음."으로 둔다.
  - "현재 문서" 개수와 목록에 새 문서를 넣는다. 해결된 "알려진 빈칸"은 지운다.
  - 다른 세션이 쓴 규칙·빈칸은 지우지 않는다.
  - 전체 내용을 `project_write`로 같은 경로에 쓴다.

## B-8. 보고
짧게 보고한다. "위키!"로 왔으면 A-5와 합쳐 한 번만 보고한다.
- 새 문서 경로, 기존 문서에 한 수정(한 줄씩), 빌드 결과(문서 N개, 경고 0)
- 건너뛴 것이 있으면 이유
- 마지막 줄: "커밋은 안 했음"
